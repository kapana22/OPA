# Expo HAS CHANGED

Read the exact versioned docs at https://docs.expo.dev/versions/v57.0.0/ before writing any code.

# Game content and presentation

- For every new game, keep editable questions, words, prompts, and sentences in a separate clearly named JSON file under `src/content/games/<game-id>.json`. Import this source into the game; do not duplicate it inside components or generated banks.
- Expose each new game's content as a separately labeled section in the local editor at `../Tools/word-editor`, and document its source and editing workflow. Preserve stable content IDs when editing text.
- Keep Georgian game descriptions short, natural, and free of long dash separators. Preserve meaning when shortening.
- Home game cards should show the cover and short description. Do not add player counts, minutes, or other metadata unless the user explicitly requests it.
- Include a matching game cover when adding a game, and verify that every catalog game resolves to an existing artwork file.
- Each independent game must have its own home card, rules, and direct flow. Do not hide independent games inside another game's mode selector. Where’s the Line is a free conversation deck without voting, predictions, timers, or scores.
- Do not launch desktop/browser previews for testing unless the user asks. Use the physical phone for visual verification; code checks may run locally.
- New covers must use existing cover files as direct image references (for example `opa-tableread.jpg`, `opa-impostor.jpg`, `opa-mostlikely.jpg`). Preserve the recurring cartoon characters, saturated blue-violet lighting, close framing, and rounded mixed-case white/lime titles. A generic purple palette with realistic adult characters or uppercase block titles does not match the established style.

# Regression rules for future changes

- The user subsequently approved the English TT cover series recorded in `design/game-cards/series-generation-v1.json`. Preserve that approved series, the OPA logo, the recurring characters and the **3:4 illustration area**. Ordinary UI text does not inherit the cover's 3D title treatment.
- Use `src/theme/theme.ts` and the existing shared UI components. Text action buttons use the lime primary / purple secondary styles and plain labels; navigation icons have named, measurable targets (iOS 44 pt, Android 48 dp). Do not fix clipping by disabling font scaling globally. At large text sizes, allow scrolling or fewer columns; ensure the last action is reachable above the keyboard/safe area.
- Use `needsSingleColumn(width, fontScale)` from `src/theme/responsive.ts` for crowded option/category/player layouts. Feed logical window width (pt/dp), never screenshot pixels. Labels wrap and content scrolls before any font shrinking is considered; check small phones and increased system text again after shared layout changes.
- Keep Android MainActivity's `fontScale` configuration handling and `plugins/withRuntimeFontScale.js` enabled across prebuilds. With the installed RN version, resume updates font metrics without replacing the running game. Verify system Settings → text-size change → return with the same turn and updated font scale; this does not promise restoration after process death.
- Do not add decorative glyph tiles (sparkles, trophies, faces, flags or generic role badges) above player names or result headings. Keep existing character avatars small and public; keep the result/status in text. Icons are for meaningful category/navigation controls, with accessible labels, rather than ornament on plain text action buttons. Mafia's excluded game-specific presentation stays outside this cleanup.
- Read the actual catalog, Flow and engine before changing a game's behavior. Herd Mentality is oral; Most Likely uses pointing; The Line is a conversation deck. Do not reintroduce writing, voting, points or random-player selection into these games without a new product instruction. Do not edit Mafia's engine, narration or sounds while its unfinished sound work is excluded by the user.
- Keep player/content IDs stable. Engines capture their own party roster; identify players by ID, not display name or mutable list index. Validate the game's existing minimum at both the UI entry and engine start. Preserve the roster's existing trim/duplicate/max-player rules rather than inventing new ones.
- Guard state-changing actions against their legal phase and, for changing questions, the current question/turn version. A completed turn must not score twice. Retain the shared transition press guard: an old second tap must not activate the next phase's button. Automatic start is only for a setup with no meaningful options and must check `phase === 'setup'` and the existing minimum so React effect re-entry cannot draw a second card. Test double actions and restart/reset whenever these paths change.
- Timer owners must stop on unmount/end/restart. Preserve the existing `GamePause` reason-based policy: inactive/background and confirmation dialogs pause, returning/closing releases only the corresponding reason. Do not speed up production timers or silently change the pause policy for QA.
- Secrets must be conditionally **unmounted**, including their accessibility labels, until deliberately revealed. `PassPhoneReveal` closes on release, new turn and any non-active `AppState`; returning must not reopen it or retain recipient confirmation. Keep `onPrivateRevealInterruption` and its tests when modifying this flow. Check native transitions and app-switcher previews separately: a JS AppState test cannot guarantee native snapshot privacy.
- `Sound.play()` is one-shot. On finish, pause **before** seeking to zero: Android Media3 retains `playWhenReady`. Share an in-flight rewind per player; never issue a stop rewind that can later reset a newer play. Invalidate pending play requests on stop, disable and release, and re-check player lifetime, request identity and enabled state after asynchronous seeking. Do not rely only on the native `playing` flag.
- Engine tests alias sound to a noop; they do **not** validate real sound behavior. Keep `tests/sound.test.ts` importing the real module with only expo-audio/WAV mocks. Cover pending restart cancellation, stop→new play ordering, rapid requests, finish, rejected seek and released players.
- `TruthDareBank` groups are `{ heat, truths, dares }` (`family`, `party`, `spicy`); generic `{ id, name, emoji, words }` categories do not belong there. The word editor and extraction validation must enforce this shape. Preserve every added text exactly once and the JSON files are the canonical source; validation must never overwrite edited content. Keep `tests/content.test.ts` and `tests/editorTruthDare.test.ts` passing.
- After a meaningful change run `npm test`, `npm run typecheck`, `npm run lint` and the appropriate bundle/native check. Repeat the changed native scenario and affected shared-component screens. Keep synthetic fixtures/debug handlers out of production behavior. Record unit, handler, screenshot, physical-touch and screen-reader evidence separately in `qa/mobile-ux-audit`; do not call unrun or blocked checks PASS.
